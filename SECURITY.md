# Security Policy

## Reporting a Vulnerability

Please **do not report security vulnerabilities through public GitHub Issues** or any other public channel. Publicly disclosing a vulnerability before it has been addressed can put users at risk.

Instead, report it privately by emailing:

**rprtuttu@gmail.com**

To help us understand and address the issue quickly, please include as much of the following as you can:

- A description of the vulnerability and its potential impact
- The affected component (e.g. backend API route, frontend code, a specific generator, the AI Builder pipeline, a generated project artifact)
- Steps to reproduce the issue, or a proof of concept, where appropriate
- The version, commit hash, or branch you tested against
- Any relevant logs or error output

## Responsible Disclosure

We ask that you give maintainers a reasonable amount of time to investigate and address a reported vulnerability before any public disclosure. We will do our best to acknowledge reports and keep you updated as the issue is investigated, but as this is a project maintained on a volunteer basis, we cannot commit to a specific response time or service-level agreement at this stage.

There is currently no dedicated security response team; reports are handled directly by the project's maintainer(s). KubeVerse does not hold any formal security or compliance certifications.

Thank you for helping keep KubeVerse and its users safe.
